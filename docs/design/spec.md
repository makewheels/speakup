# SpeakUp — 产品功能文档

> 这份文档面向两类读者：
> - **设计师 / Claude Design**：按"页面 → 状态 → 元素 → 交互"逐节描述，可直接拿去画 UI
> - **开发者**：按 MVP / V1.1 / V2 划分迭代范围，对应代码改动点

---

## 1. 产品定位

**一句话**：看场景题 → 开口说英语 → AI coach **暴露你和母语者日常版之间的差距** → 把差距沉淀成复习项 → 间隔回顾，逐渐拉平。场景配图可选，默认关闭（`IMAGE_ENABLED=false`）。

**目标用户**：成年人、能读写英语但开口卡住的中国学习者，自己 + 朋友圈试用。

**核心痛点**：
1. 不敢开口、想不起词
2. 说出来 Chinglish、不地道

**不解决**：听力、考试技巧、儿童英语启蒙。

**产品气质**：客观、克制、不哄、不打鸡血。像一个不评判你的私人老师。

---

## 2. 产品本质：差距，不是纠错

这是整个产品最核心的判断，影响 prompt / UI / 数据模型所有层：

| 纠错产品（不是我们）| 差距产品（我们）|
|----|----|
| 你说错了，这是对的，下次别错 | 你这么说能听懂，但母语者会这么说，差在 X / Y / Z |
| 修对错 | 拉近"听起来像本地人"的距离 |
| 默认用户水平差 | 默认用户已经能用，要把"能用"推到"地道" |
| 输出整段 corrections | 输出最多 3 条 gaps，每条带原话片段、同范围改写与 why |

**衡量"做对了"的瞬间**：用户练完一次说"哦，原来母语者这么说"。

**核心循环**：

```
看场景题 → 开口说英语 → AI 暴露差距 → 问 coach / 看懂为什么 → 保存差距为复习项
                                                                         ↓
                               举一反三 ← 原题重练 ← 隔天/隔三天回顾
```

---

## 3. 用户旅程

**首次使用（≤ 2 分钟到第一次反馈）**：
打开 → 输手机号 → 进入练习主页 → 看到一张场景图 → 按住/点击录音 → 说几句英语 → AI 给纠正 → "啊原来这么说" → 决定是否保存错题 → 看下一张图 / 退出。

**回访（每天 5-15 分钟）**：
打开 → 默认进练习主页 → 看到"今天有 N 个错题待复习"小条 → 选择"继续练新的"或"复习错题" → 完成后看到打卡 +1。

## 4. 页面规格

### 4.1 登录页

**入口**：未登录用户访问任何页面跳转至此。
**出口**：登录成功 → `/practice`。

**屏幕元素**：
- 顶部：产品名 `SpeakUp` + 副标题 `See a scene, speak to get it done. AI shows you how a native would say it.`
- 手机号输入框（数字键盘、最多 11 位）
- 进入按钮（手机号合法时启用）
- 提示文字：`Enter your phone to sign up — no code needed.`（明示 MVP 状态，避免误解）

**状态**：
- 空白态（按钮 disabled）
- 输入中
- 提交中（按钮 loading）
- 错误（手机号格式不对、网络失败）

**交互细节**：
- 输入框 autofocus
- 回车提交
- 手机号格式 `^1\d{10}$`，前端先校验

---

### 4.2 练习主页（核心页面）

**入口**：登录后默认进入；底部导航"练习"；反馈页点"下一张"；错题本列表点某项进入"原题重练"也复用此页。

**屏幕区域（从上到下）**：

1. **场景图片**（可选，`IMAGE_ENABLED=false` 默认关闭，关闭时显示占位区）：加载中显示骨架屏
2. **录音区**（图/占位区下方居中）
3. **转录文字区**（说话过程实时显示）
4. **操作按钮区**（录音停下后出现）
5. **底部导航**（练习 / 错题本 / 我的）

**状态**：

| 状态 | 屏幕展现 |
|------|---------|
| **加载场景** | 图片区显示骨架屏；录音按钮 disabled |
| **场景就绪 · 待录音** | 图片（或占位区）显示，下方居中大圆按钮 🎤 "Hold to speak" 或 "Tap to speak" |
| **录音中** | 一行三按钮：左 `⏸ 暂停`（暂停后变 `▶ 继续`，计时冻结）+ 中间红色脉动大按钮 `⏹ Stop`（完成→转写→自动评估）+ 右 `🗑 重录`（丢弃本段回到待录音）；时长 `0:12`；转录区实时显示识别出的英文 |
| **录音结束 · 待提交** | 转录文字静态展示；下方两按钮 `Get feedback` / `Retry` |
| **AI 评估中** | 按钮变 loading |
| **看反馈** | 见 4.3 |

**交互细节**：
- 录音按钮是整页最大的可点击区域（≥ 80px），避免点不准
- 录音过程允许中途停止；停止后保留已转录的文字
- "Retry" = 抛弃当前转录，重新开始（要给一个轻微确认动画但不弹窗）
- 转录文字若为空，"Get feedback" 按钮 disabled
- Chrome 之外的浏览器，进入页面就提示不支持语音识别

**文案规范**：
- UI 标签/按钮/提示用英文（见 §「界面语言」），简洁、客观
- 不用"棒棒哒"、"加油"这类
- 不写"AI 老师"，写"AI coach" 或 "AI feedback"

### 4.3 AI 反馈展示（练习主页同屏切换）

**入口**：4.2 点 `让 AI 评估` 并得到响应后。
**出口**：用户选择 `添加到复习` / `重说一遍` / `下一张图`。

**屏幕区域**（垂直滚动，**分三层**对应 prompt 输出的三个层）：

#### 第一层：核心结论（顶部，大字）

- 一句话 summary，例如 `Your meaning is clear, but the phrasing reads bookish — natives would shorten and contract.`
- 视觉：大号字体、留白多、不带任何额外修饰

#### 第二层：差距对比（中间，列表）

每一条 gap 一卡，按重要性从上到下排。类型与中文短标题合并在卡片头部；首屏主体固定为「你说 / 这样说 / 为什么」三行，不再单独展示 Meaning。只有能把同一规律迁移到另一个真实语境时，才在可展开区域提供另一个例句及其中文翻译；与「这样说」重复或没有额外教学价值时，整个入口不显示：

```
┌────────────────────────────────────────────┐
│  YOU SAID                                  │
│  there is some peoples eating food         │
│                                            │
│  这样说                                  │
│  a few people are having a meal            │
│                                            │
│  WHY · grammar                             │
│  "people" is already plural — no -s. And   │
│  "eating food" feels redundant; native     │
│  speakers say "having a meal" or just      │
│  "eating".                                  │
└────────────────────────────────────────────┘
```

- 「你说」标签和原文统一用警示红；「这样说」用主色；「为什么」保持中性，不再随字段切换颜色。
- category 与 title 合并为一行，不再额外占一列。
- 数量不固定；三行核心对比默认展开，有教学价值的迁移例句默认折叠。

#### 第三层：独立标准答案（底部）

- `标准答案`：由另一个独立请求只基于题目作答；上下文不包含用户原话、gaps 或历史回答（`standardAnswer`）。
- 默认折叠；播放按钮放在折叠触发器外，播放不改变展开状态。

结果文字可选中，底部浮条提供「加入笔记」；不自动生成笔记。

#### 底部操作区

- 结果页最后一个区块提供「分享本次结果」，位于重说/下一题操作之后；手机优先打开系统分享面板，不支持时复制完整文案和链接，不需要先回历史页。
- 每个 gap 的「加入复习」用于手动收录/取消该错题；`saveToReview=true` 的高价值错题仍可由后端自动收录。
- 次操作：`重说一遍` — 不封顶、按钮常驻且不带次数；当前轮次只在页面顶部徽章展示
- 次操作：`下一张图`

**状态**：
- 评估失败：单条提示 `评估失败，重说一遍` + 重试按钮
- 用户说话太短（< 3 词）：跳过差距分析，提示 `多说几句试试，描述你看到的细节`
- 已保存：`添加到复习` 变 `已添加 ✓`，再点可从复习中移除

**交互细节**：
- gap 的核心三行默认全展开；迁移例句存在时默认折叠，不存在时不保留空入口。
- 结果文字可用浏览器原生选区手动摘录。
- 在反馈页静默预取下一张图（用户决定下一步时图已就绪）

### 4.4 复习页（原"错题本"）

> **命名说明**：用户视角看到的 tab/页面叫 `复习`（不是"错题本"），因为里面的项目不一定是单词或错题 — 也可能是地道表达、整句改写、语法点。"复习项" 是统一抽象。

**入口**：底部导航 `复习`。
**出口**：进入某项 → 4.5 原图重练；进入某项的"举一反三" → 4.6。

**屏幕区域**：

1. **顶部摘要卡**
   - `共 N 个复习项`
   - `今日待复习 M 项`（基于间隔算法）
   - 按钮：`开始今天的复习`（M > 0 才显示）
2. **筛选/切换**
   - 全部 / 今日待复习 / 已掌握（轻量 tab）
3. **复习项列表**（每项一卡）
   - 左：场景图缩略（48 × 48 圆角）
   - 中：`there is some peoples → there are a few people` + 原因摘要
   - 右下：上次练习日期 + `复习 × N`
   - 右上小标签：`待复习` / `已掌握`
   - 点击卡片：展开"原图重练 / 举一反三 / 详情"三个动作（或直接进 4.5）

**状态**：
- 空态（新用户）：文案 `还没有复习项。去练习里说一段试试` + 跳转练习的按钮
- 加载中骨架屏

**交互细节**：
- 滚动到底自动加载下一页
- 错题项右滑可删除（移动端手势）
- 长按可标记"已掌握"

---

### 4.5 原图重练页

**入口**：4.4 点某错题，或反馈页提示"3 天前的同款错题，再说一次试试"。
**出口**：完成后回 4.4 / 进入下一题。

**屏幕区域**：

1. 顶部小条：`复习 · 第 1 / N 题`
2. **场景图**（同当时的图）
3. **上次错的地方**（折叠卡片）
   - 默认收起，标题 `上次你这样说`
   - 展开后：用户原话 + AI 的修正
4. **录音区**（与 4.2 相同）
5. **转录 + 让 AI 评估** 流程同 4.2
6. **AI 反馈** 同 4.3，但额外加一行 `比上次：进步 / 同样错误 / 新错误`

**交互细节**：
- 默认上次错的地方是收起的，鼓励用户先自己说（避免照抄）
- 用户主动展开就给看
- 若本次同一点说对了，UI 给一个"克服了一个错题 ✓"的小提示（不弹窗、不动画夸张），且该错题间隔倍增

---

### 4.6 举一反三复习页（V1.1，设计先画出来）

**入口**：4.4 / 4.5 完成后建议进入；或单独 tab。
**出口**：完成 → 回 4.4。

**屏幕区域**：

1. 顶部小条：`举一反三 · 考点：动词单复数`
2. 提示卡片：`你之前在 "there is some peoples" 上出错。换一张图，看你还会不会犯`
3. **场景图**：AI 按"同考点不同场景"新生成的图
4. 录音 + 转录 + 评估流程同 4.2 / 4.3
5. 评估时额外检查：`本次是否仍出错同一类语法点`
6. 反馈页加一行总结：`这一类错你已经 N/M 次说对`

**MVP 范围说明**：举一反三这页 demo 阶段可以先用 "把原图换一张同 topic 的图" 当 placeholder，AI 同考点重判不严格。等通义万相接回再升级。设计图建议画出来明确产品方向。

### 4.7 个人中心（轻量）

**入口**：底部导航 `我的`，或右上角头像。
**出口**：退出登录回 4.1。

**屏幕元素**：
- 顶部资料卡：自定义头像（未设置时取昵称首字符）+ 昵称（首次为 `User1234`）+ 手机号脱敏；点击整张卡进入独立资料编辑页
- 资料编辑页：可上传/恢复默认头像、修改昵称；手机号只读并明确标记暂不可修改
- 统计卡片
  - `连续打卡 N 天`
  - `总练习 N 次`
  - `错题 N 个，已掌握 M 个`
  - `本周练习曲线`（小柱状图）
- 设置项
  - 退出登录
- 关于
  - 版本 / 反馈方式（一个邮箱）

昵称在独立资料页编辑，保存后同步刷新个人页和本地登录态；输入规范为 1–24 个字符，自动整理首尾及连续空白。头像支持 JPG、PNG、WebP，最大 5 MB，上传后同步刷新；手机号当前不进入任何可写请求。

### 4.8 底部导航

MVP 两个 tab（`我的` V1.1 再加）：

## 5. 设计约束

- **手机优先**：所有页面按 iPhone Pro 375 × 812 设计；桌面只保证能用，不优化
- **浏览器**：必须 Chrome（语音识别）；非 Chrome 在登录页就拦截提示
- **界面语言**：UI 标签/按钮/提示跟随用户语言设置，中文模式不保留 `Correction` / `Native` / `Meaning` 等未翻译标签；英语表达本身保持英文，AI 的讲解性内容可用中文。
- **气质关键词**：客观、克制、私人感、不哄、不打鸡血
- **配色不强约束**：留给设计师发挥，但避免儿童化、避免游戏化、避免大量彩色块
- **不要**：连击 streak 火苗 / XP 进度条 / 等级勋章 / 排行榜 / 弹窗"今天真棒"

## 7. 数据模型（简版）

```
users:
  _id, phone, nickname, avatarKey?, avatarVersion?, lastLoginAt, updatedAt?, createdAt

sessions:               // 一次"看图说话"
  _id, userId, topic, imageUrl, attempts[], createdAt

  attempts:
    transcript, correctedText, corrections[], tips[],
    whatISee, missedElements[], suggestedVocabulary[],
    createdAt

mistakes:               // V1.1 新增，从 attempts 自动提取
  _id, userId, sessionId, attemptIndex,
  original, corrected, reason, grammarPoint,
  imageUrl,             // 用于"原图重练"
  reviewCount, easiness, interval, nextReviewAt,
  mastered, createdAt

vocabulary:             // 生词（独立于 mistakes）
  _id, userId, word, chinese, contextSentence,
  reviewCount, easiness, interval, nextReviewAt
```

## 8. 图片来源策略（多用户共用池）

- **MVP**：`loremflickr.com` 按 topic 关键词随机取，全用户共用，撞图无所谓（反馈是个人的）
- **V2**：迁移到"通义万相预生成 → 腾讯云 COS"
  - 后台 cron 每天/每周生成 N 张新图，按 topic 打标签存入 `image_pool` 集合
  - 用户请求时从池随机取，附带的 `imageUrl` 是 COS 公网 URL（AI 也能访问）
  - 不追踪"用户看过哪些图"，允许撞图

主题：MVP **全随机**，不让用户选 topic。topic 标签后台用于"举一反三时按同 topic 拿图"。

## 9. 文案 / 语气样本

| 场景 | 推荐 | 避免 |
|------|------|------|
| 加载图片 | `准备图片中...` | `小老师正在为你寻找有趣的图片哦～` |
| 录音前 | `看着图，用英语描述` | `加油！开始你的英语之旅` |

## 10. AI Prompt 设计原则

整个产品的 AI 行为靠 system prompt 控制。下面 5 条是必须保持的判断，**改 prompt 时不能违反**：

### 五条原则

1. **核心任务**：暴露用户表达与"母语者日常版"的差距。不是纠错，是 expose gap。
2. **范围限定**：只在用户已表达的内容上做。不脑补图里没说的、不扩写。
3. **目标水平**：星巴克邻桌的母语者 — natural daily English。不是 BBC 主播、不是文学英语、不是 GRE 词汇。
4. **分层输出**：核心结论（一句）+ 按重要性排序的差距点（每条带原话、同范围改写、why、category）；不再附整段纠正版。
5. **气质**：不夸 / 不元话语 / 不疗愈 / 不打鸡血。说事不说人。

### 四条明示底线（写进 prompt 的 WHAT NOT TO DO）

| 底线 | 为什么 |
|------|------|
| 不脑补图里没有 / 用户没说的内容 | 防止 AI 幻觉、防止把用户原话改成别的 idea |
| 不改用户想表达的核心 idea | 学习闭环：只教 "how to say YOUR idea naturally"，不教 "say something else" |
| 不为炫技推罕见词 | 跟"日常版"原则呼应；母语者也不秀词 |
| 不写"作为 AI 老师..."等元话语，不写"加油"鼓励 | 维持 signal-to-noise |

### 输出 schema（JSON）

```json
{
  "summary": "一句中文总评",
  "score": 6.5,
  "gaps": [
    {
      "title": "中文短标题",
      "original": "用户原话中的连续短语或完整句子",
      "better": "相同范围的自然改写",
      "chinese": "better 的中文提示",
      "example": "可选：同一规律在另一个语境中的英文例句",
      "exampleChinese": "可选：example 的自然中文翻译",
      "why": "简短中文原因",
      "category": "task | grammar | naturalness | vocabulary | register"
    }
  ],
  "progress": null
}
```

最多 3 条，按重要性排序。同一句里的相关问题尽量合并；短语问题可短改，需要重写时可以覆盖完整句子，不要拆成一两个词的碎片。

### 反馈语言策略

- `summary` / `gaps[].why`：中文（快速理解）
- `gaps[].original` / `gaps[].better`：英文（原文 / 改写都是英文）
- `gaps[].chinese`：`better` 的简短中文提示
- `gaps[].example` / `exampleChinese`：仅在有可迁移的新例句时填写；不能复述或轻改 `better`
