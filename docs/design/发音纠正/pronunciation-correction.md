# 发音纠正 · 产品与实施方案

> 状态：设计定稿，待体验启动（2026-08-24）。供应商选型调研见 `docs/评测/发音纠正选型调研.md`；本文是产品形态与落地计划，不重复厂商横评。
>
> 需求原点（用户原话提炼）：要的不是分数，是**纠正**——哪个词错、我发成了什么、正确的什么样、重音对比（"重音一个在首字母，对的什么样"）。

## 背景

SpeakUp 现有链路：ASR 把录音转文字 → 文本评估给内容/语法/表达反馈。两者都不保留音素、重音、韵律等声学信息，无法回答"我这个词发音对不对"。本功能新增专用口语评测能力，补齐声学诊断。

## 目标 / 非目标

**目标**

1. 结果页新增异步「发音」卡：一次最多 3 个最值得改的词，每个词给出——目标词、你的发音（IPA）、正确发音（IPA）、重音对比、一句人话解释、你的原音裁切回放、标准音、内联「再练一次」。
2. 「再练一次」形成单词级闭环：听标准 → 读 → 引擎单词模式秒级评分 → 过了标 ✅、没过继续对比。最小对立对比练（sailor/seller 连播跟读）作为同循环的可选招式。
3. 供应商可换：引擎层留 provider 接缝，换厂商只换实现不动上层。

**非目标**

- 不让大模型当评分器（它不听音频做判断，只做文案，见 §3）。
- 不因本功能新增永久原始音频存储（§6）。
- 首发不做：错题本联动（"没过的自动进复习队列"）、教练自由点评（音频模型听韵律）——均为后续延伸。

## 3. 三层分工（核心架构共识）

| 层 | 职责 | 不做什么 |
|---|---|---|
| **评测引擎**（尺子） | 出结构化事实：检测音素 vs 参考音素、逐音素分、重音该不该 vs 实际、词/音素时间戳 | 不出自然语言建议、不出标准音频 |
| **音素规则库**（药方） | 人工维护高频音素对立的口型/舌位教法（th/s、v/w、l/r、eɪ/ɛ、ŋ/n 尾、重音类型等，首发 15–20 组），数据文件 + 代码审查增补 | 不自动生成 |
| **文字 LLM**（文案） | 拿事实 + 规则库组装成一句自然中文；可结合用户水平换口吻 | 不判断对错、不编教法、**不接收音频** |

配套：

- **标准音**：自建 TTS（DashScope，复用现有例句朗读组件）合成目标词/句。
- **你的原音**：按引擎时间戳裁切本次录音回放（前端 `<audio>` seek 实现，不新增音频文件）。
- 引擎返回的音素符号经官方《音素→国际音标》映射表转 IPA 展示（查表，非模型生成）。

为什么文字模型而非音频模型做文案：到文案层"听"的活已由引擎完成，再喂音频只会引入重复判断、幻觉与成本，无新信息。音频多模态模型（Qwen2.5-Omni 等）的合理位置是候选路线 B 或后续"教练自由点评"，见 §5。

## 4. 评测模式选择（腾讯云模式编号）

两段式：

1. **第一遍 · 模式 2（段落）**：整段回答 + ASR 转写作为参考文本（回答 ≤30 词时用模式 1）。拿整体分、逐词 `PronAccuracy`、逐词时间戳 → 挑 ≤3 个低分词。不用模式 3（自由说）做主链路：无参考文本时"哪个词错"判不准。
2. **第二遍 · 模式 4（音素纠错）**：按时间戳裁低分词片段送检，拿检测音素 vs 参考音素、`Stress` vs `DetectedStress`、音素时间戳。

单次练习成本 ≈ 模式 2 一次 + 模式 4 三次 ≈ 4–5 计费单位 ≈ 0.02 元（腾讯后付费口径）。

## 5. 供应商路线（A/B，用数据定）

- **路线 A · 腾讯 SOE-N**：上述两段式；体验包 9.9 元/1 万次。**未开通、未购买，需用户点头。**
- **路线 B · 纯 Qwen-Omni**（DashScope 现有密钥，零新供应商）：音频 + 转写喂入，要求输出结构化 JSON（词/检测音素/参考音素/重音/建议）。风险：一致性、幻觉未经校准。
- **决策方式**：同一条用户录音两路线并排跑，输出对比给用户看；正式验收门槛（近音词 Top-1≥90%、误报≤10%、教师相关≥0.75 等）见调研文档 §7，需 200–300 条带教师标注录音，属后续阶段。

provider 接缝：`services/pronunciation/` 内定义 `PronunciationProvider` 接口（`evaluate_pass1(audio, ref_text)` / `evaluate_word_clip(audio_clip, word)`），`MockProvider`（开发/集成期）、`TencentSoeProvider`、`QwenOmniProvider` 三实现可插拔。

## 6. 产品形态与集成

- 结果页「发音」卡**异步**出现，不阻塞主结果；失败/无录音时静默不出现，可稍后重试。
- 卡片视觉沿用结果页 token 体系（橙/警示色描边卡，与蓝=纠正版、绿=标准答案同构）；深浅主题走语义 token 自动跟随。演示样张见 2026-08-24 的 HTML 原型（tmp 临时件，未入库）。
- i18n：中英双文案随现有 useI18n。
- 持久化：只存结构化结果（问题词、音素、分数、时间戳、供应商与模式），attempt 挂 `pronunciation` 字段；**不存原始音频副本**（回放用现有 recordingUrl + seek）。

## 7. 隐私与合规

- 音频发给供应商即第三方处理：体验阶段只用**用户本人授权**的录音（用户确认用哪条或新录）；上线前隐私政策/麦克风说明补充第三方处理披露（调研 §2.5）。
- 供应商密钥只放服务端，最小权限、可轮换。
- 路线 A 数据境内处理；路线 B 同 DashScope 现有链路。

## 8. 实施阶段

| 阶段 | 内容 | 前置 |
|---|---|---|
| P1 集成骨架 | 真组件 + `MockProvider` 接入结果页；后端路由 + provider 接缝；单测/组件测试；本地走查截图；**不上生产** | 无（不花钱） |
| P2 体验定供应商 | 用户授权录音 → A/B 并排跑 → 对比输出定路线；若 A：买 9.9 体验包 | 用户授权录音 + 购买点头 |
| P3 上线 | 真 provider 接入、feature flag 开启、生产验证、隐私文案更新 | P2 结论 |
| P4 验收（可选） | 200–300 条教师标注录音试点，按调研 §7 门槛判 | 录音+标注资源 |

## 9. 未决事项

1. 体验录音授权：用生产库哪条（需确认是用户本人账号）或新录一条。
2. 腾讯 SOE 开通/购买：待用户点头。
3. 错题本联动、教练自由点评：首发不做，观察数据后再定。
4. 规则库首发 15–20 组音素对立的清单与教法文案，P1 期间人工编写。
