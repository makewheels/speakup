# SpeakUp 发音纠正能力选型调研报告

- 调研时间：2026-08-18（所有官方页面均于当日通过 web_fetch 查证）
- 背景：SpeakUp 现链路为「用户录音 → 阿里云百炼 Qwen ASR → DeepSeek 基于文本对比场景要求给反馈」。该链路只有文本，发音层错误（重音位置错、近音词混淆如 sailor/seller、th/s 不分、元音不饱满等）完全检测不到。本调研为补齐"发音纠正"能力选型。

> - API 文档 https://cloud.tencent.com/document/product/884/32605

**⚠️ 重要状态**：产品页明确显示"口语评测（基础版）"（即原智聆口语测评 SOE）**已停止迭代并将下线**，官方推荐转用"口语评测（新版）"。新版产品页/文档入口在公开网络上未能定位到（站内搜索页为动态加载，抓不到结果），**接入前必须先提工单或在控制台确认新版入口、API 兼容性与价格**。以下能力/价格信息均为基础版文档所载，供评估产品成熟度参考。

### 能力范围
- 语言：中文、英文（`ServerType`：0=英文，1=中文）
- 评测模式（`EvalMode`）：0=单词/单字、1=句子、2=段落、3=**自由说**、4=单词音素纠错、5=情景评测、6=句子多分支、7=单词实时、8=拼音评测
- 评分维度：发音准确度、流利度、完整度（官方称与专家打分拟合度 95%+）
- **音素级结果：支持**。返回 `Words[].PhoneInfos[]`，每个音素含 `Phone`（实际识别音素）、`ReferencePhone`（参考音素）、`PronAccuracy`（音素准确度）、起止时间、**`Stress`/`DetectedStress`（重音标注与实测重音）** —— 直接命中"重音位置错、近音词混淆"需求
- 场景定位：**全年龄段**，覆盖 K12 也覆盖成人（官方应用场景含"企业招聘内训"）；`ScoreCoeff` 苛刻指数 1.0（儿童）～4.0（成人严格打分），可按成人调参
- 支持自定义音素文本输入（`TextMode=1`）

### API 形态与接入
- 接口：`TransmitOralProcessWithInit`（初始化+音频流传输合一），腾讯云标准 TC3-HMAC-SHA256 签名 HTTP API，Python 有官方 SDK（tencentcloud-sdk-python）
- 音频要求：16kHz / 16bit / 单声道；raw/wav/mp3/speex
- 限制：API 调用生命周期 30 秒；流式分片间隔 ≤5s；`WorkMode` 支持流式/非流式一次性评估（**非流式对 SpeakUp 这种"录完再传"的场景最简单**）

### 价格（基础版）
| 计费方式 | 价格 |
|---|---|
| 后付费 | **0.005 元/次**（5 元/千次），月结 |
| 资源包（限时优惠） | 1 万次/1 个月：9.9 元 |
| 资源包 | 15 万次/1 年：600 元（4 元/千次）；100 万次：3,750 元（3.75 元/千次）；更大量低至 3 元/千次 |

- 单词/句子模式：1 次请求 = 1 次调用；段落/自由说模式按文本长度折算，每 20 个单词计 1 次（向上取整）
- 英文版与中文版分开计费，资源包不共享
- 免费额度：文档未提及调用次数免费额度；并发 0–50 个免费，超出 30 元/个
- 按 SpeakUp 场景估算：句子模式每天 1 万次评测 ≈ 50 元/天（后付费），成本极低

## 2. 其他云厂商

### 2.1 科大讯飞 语音评测（ISE）

> 来源：API 文档 https://www.xfyun.cn/doc/Ise/IseAPI.html （产品页 https://www.xfyun.cn/services/ise 为动态渲染，能力信息以 API 文档为准）

- 语言：中文普通话、英文
- 英文题型（`category`）：`read_word` 词语、`read_sentence` 句子、`read_chapter` 篇章、`simple_expression` 情景反应、`topic` 自由题/口头作文、`retell` 复述、`picture_talk` 看图说话、`oral_translation` 口头翻译 —— **题型最丰富，含自由表达类**
- 英文评分维度：准确度、流利度、完整度、标准度（`ise_unite=1` + `extra_ability=multi_dimension` 开启分项）；另有音节得分 `syll_score`、**重读检错 `syll_accent`**、停顿/连读/升降调检错（`werr_msg`）
- **音素级结果：支持**，`extra_ability=syll_phone_err_msg` 返回音素错误详情；`dp_message` 标注增/漏/回/替换读；`extra_ability=pitch` 可返回基频
- **成人场景：支持**，`group` 参数可设 `adult`（影响评分模型）
- API 形态：**WebSocket**（`wss://ise-api.xfyun.cn/v2/open-ise`，HMAC-SHA256 URL 签名），音频 16kHz/16bit/单声道，PCM/WAV/MP3/Speex，单次会话 ≤5 分钟；参考文本需加 BOM 头
- **价格：未查到**。官网服务页价格区块为 JS 动态加载，文档站无价格页（https://www.xfyun.cn/doc/Ise/IsePrice.html 404），需在讯飞开放平台控制台查看或询价

### 2.2 微软 Azure Speech — Pronunciation Assessment（发音评估）

> 来源：
> - 功能文档 https://learn.microsoft.com/en-us/azure/ai-services/speech-service/how-to-pronunciation-assessment （页面更新于 2026-07）
> - 定价 https://azure.microsoft.com/pricing/details/speech/ + Azure Retail Prices API

- **评分粒度（`Granularity`）：Phoneme（音素）/ Word / FullText 三档**，音素级时返回全文、单词、音节、音素四层分数
- 评分维度：AccuracyScore（准确度）、FluencyScore、CompletenessScore（完整度，需参考文本）、**ProsodyScore（韵律：重音、语调、语速、节奏**，SDK 1.35+，目前仅 en-US locale）
- `EnableMiscue` 可检测 Omission/Insertion（漏读/多读）
- **两种模式**：scripted（给参考文本跟读）和 **unscripted（无参考文本自由说）** —— 后者很适合 SpeakUp 的开放对话场景
- 支持流式、无限时长；>30s 用 continuous 模式（该模式不支持 miscue）
- 发音评估使用专用 STT 模型版本，与普通 STT 不同
- 语言支持：依赖 Speech 的 pronunciation assessment 支持语言列表（英语为主，详见 language-support 页）
- **API 形态：Speech SDK（Python `azure-cognitiveservices-speech` 可用），不是纯 REST**；FastAPI 后端集成需引入 SDK，音频经 SDK 传入
- **价格**：官方文档明确"发音评估按标准 Speech-to-Text 费率计费"。经 Azure Retail Prices API 查证（2026-08-18）：**S1 Speech To Text = $1.0/音频小时（eastus）**；**免费层 F0：每月 5 音频小时**（定价页所列）。eastasia 区标准 STT 行未在 API 返回中直接列出，按官网说明各区域以控制台为准
- 按 SpeakUp 估算：每次评测平均 10s 音频 → $1/小时 ≈ 每次 0.02 元级（约 ¥0.02/次，按 $7.2 汇率约 ¥0.02），但单价仍显著高于腾讯云；且国内访问海外 region 有延迟/合规考虑

## 3. 大模型路线（多模态音频 LLM 直接听音评估）

### 3.1 能力现状

- **纯文本 LLM 不可行**：发音信息在 ASR 转写时已丢失（sailor/seller 转写后无法区分）。
- **Qwen2-Audio**（arXiv:2407.10759）：面向音频理解/语音对话/音频推理，官方技术报告**未涉及音素级发音诊断**；其 ASR 能力强，但"听出发音哪里错"与"听懂内容"是不同任务。
- **GPT-4o audio / Gemini 音频输入**：同理，是通用音频理解模型，无结构化音素评分输出。

### 3.2 学术/工程实践（arXiv 检索，2026-08-18）

| 论文 | 时间 | 做法 |
|---|---|---|
| Pronunciation Assessment with Multi-modal Large Language Models（arXiv:2407.09209） | 2024-07 | speech encoder + adapter 对齐音频与文本嵌入，LLM 预测准确度/流利度分数，与既有 baseline 有竞争力 |
| Exploring the Potential of Large Multimodal Models as Effective Alternatives for Pronunciation Assessment（arXiv:2503.11229） | 2025-03 | **直接用 GPT-4o 听音频做多级发音评分与反馈生成**，探索 LMM 与传统方法结合 |
| English Pronunciation Evaluation without Complex Joint Training: LoRA Fine-tuned Speech Multimodal LLM（arXiv:2509.02915） | 2025-09 | LoRA 微调语音多模态 LLM，同时做评分与误发音检测，与人工分相关性高 |
| Read to Hear: A Zero-Shot Pronunciation Assessment Using Textual Descriptions and LLMs（arXiv:2509.14187） | 2025-09 | 把语音信号转成文本描述喂给 LLM 做零样本评估 |

### 3.3 结论

该方向 2024–2025 研究活跃、进展快，但：
- 均为**研究原型**，依赖 speechocean762 等学术基准，**无生产级音素级诊断 API**；
- 商用 API（GPT-4o audio）成本高（音频 token 计费）、分数一致性/可解释性不如专用引擎，且无法稳定输出音素级结构化结果；
- 适合作为**反馈文案生成层**（把专用引擎的结构化评分翻译成自然语言建议），不适合替代评分引擎本身。

## 4. 开源路线（自建）

### 4.1 可用资产

- **speechocean762 数据集**（https://github.com/jimbozhang/speechocean762 ，另有 HuggingFace `mispeech/speechocean762`）：5,000 句非母语英语朗读（**母语为中文，50% 儿童 + 50% 成人**——与 SpeakUp 用户画像高度匹配），16kHz，5 位专家独立打分；标注含句子级（准确度/流利度/完整度/韵律 0–10）、单词级（准确度 + **重音 5/10 分**）、**音素级（goodness 0–2 + 误发音映射：canonical phone → pronounced phone）**；**允许商用**。
- **wav2vec 2.0 / 自监督路线**：arXiv:2204.03863（CTC 微调 wav2vec2 + 逐层表征 + BiLSTM，在 Speechocean762 上超越 baseline）；经典 GOP（Goodness of Pronunciation）方法基于 CTC/Kaldi 后验概率。
- **Montreal Forced Aligner**（https://github.com/MontrealCorpusTools/Montreal-Forced-Aligner ，MIT，活跃维护至 MFA 3.0/2026）：音素级强制对齐，输出 TextGrid，可作 GOP 流水线的对齐前端。

### 4.2 自建成本与效果评估

- 典型自建流水线：MFA/对齐 → wav2vec2 音素表征 → GOP/回归头打分 → 在 speechocean762 上训练校准。
- **成本高**：需语音算法工程投入（训练、校准、与人工分对齐）、GPU 推理资源；学术 SOTA 与商业引擎（拟合专家 95%+、多年线上打磨）仍有差距，尤其重音/韵律维度。
- **收益**：零边际成本、数据自主。
- **结论**：不建议作为首发方案；可作为长期储备（例如用 speechocean762 训练一个轻量误发音分类器做离线抽检，或日后评测量极大时降本）。

## 6. 推荐方案

### 首选：腾讯云口语测评（SOE 系列）

**理由**：
1. **能力精准命中**：音素级 `PronAccuracy` + `ReferencePhone/Phone` 对比能直接检出 sailor/seller、th/s、元音不饱满类错误；`Stress/DetectedStress` 直接检出重音位置错误——这是 SpeakUp 缺失的两类核心能力；
2. **场景匹配**：单词/句子模式对应场景跟读，`EvalMode=3` 自由说对应开放对话；`ScoreCoeff=4.0` 面向成人；非流式一次性评估契合"录完再传"；
3. **价格最低**：0.005 元/次（句子模式），比 Azure 便宜约一个数量级，免费并发 50 足够初期；
4. **接入最轻**：标准腾讯云 HTTP API + 官方 Python SDK，与现有 FastAPI 后端无缝。

**前置动作（必须）**：提工单/联系腾讯云销售确认"口语评测（新版）"的产品入口、API 是否与基础版兼容、新版价格，因为基础版已宣布停止迭代下线。若新版不可得或价格劣化明显，转备选。

### 备选：Azure Speech Pronunciation Assessment

**理由**：音素粒度 + prosody（重音/语调/节奏）完整，**unscripted 模式无需参考文本**（SpeakUp 开放对话场景友好），Python SDK 成熟，文档活跃（2026-07 更新），F0 每月 5 小时免费够原型验证。
**代价**：$1/音频小时（约 ¥0.02/次按 10s 计，是腾讯云 4 倍+）、SDK 而非纯 REST、海外 region 延迟与数据出境合规需评估（可选 Azure 中国区，但需单独确认 pronunciation assessment 在世纪互联运营区的可用性与价格——**未查到**）。

### 远期储备：讯飞 ISE（诊断字段最细，需询价与 WebSocket 接入评估）；开源自建（speechocean762 + wav2vec2，量起来后再做）。

### 集成方式草图（首选方案，插入现有链路）

现有链路：`录音 → Qwen ASR → DeepSeek（对比场景要求 → gaps + native version）`

改造为并行双分支：

```
用户录音(转 16kHz/16bit/单声道 wav)
   ├── 分支A（现有）：Qwen ASR → 文本
   └── 分支B（新增）：腾讯云 TransmitOralProcessWithInit
        - 有明确目标句（跟读/场景范句）：EvalMode=1 句子模式，RefText=目标句
        - 开放对话无目标句：EvalMode=3 自由说
        - ServerType=0(英文), ScoreCoeff≈3.0–4.0, WorkMode=1(非流式)
        → 音素级 PhoneInfos + Stress/DetectedStress + 总分
两分支结果汇合 → DeepSeek prompt 注入：
   - 现有内容：场景要求、ASR 文本、内容 gaps
   - 新增结构化发音数据：低分音素列表(实际音素 vs 参考音素)、重音错误词、流利度/完整度
→ 大模型统一产出：用词/语法 gaps + 发音问题诊断（中文解释 + 示范）+ native version
```

要点：
- 分支 B 与分支 A 并行调用，总延迟取决于较慢者（SOE 非流式一次性评估，通常亚秒～秒级）；
- 发音结果以结构化 JSON 注入 prompt，由 DeepSeek 负责"翻译"成对学习者友好的中文反馈，避免直接把原始分数丢给用户；
- 评测结果（音素分、重音错误）建议落库，支撑后续"发音弱项画像"（如统计 th/s 错误率）——这也是后续接 evals 体系的数据基础；
- 音频文件建议保留在 OSS，便于后续用 speechocean762 类方法做离线抽检/自建模型验证。
