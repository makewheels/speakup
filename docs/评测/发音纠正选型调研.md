# SpeakUp 发音纠正能力选型调研报告

- 调研基准日：2026-08-23
- 调研范围：英语单词/音素准确度、词重音、流利度与韵律、近音词辨析、费用、接入复杂度和数据合规
- 当前状态：**本轮只完成调研和文档更新，尚未接入任何发音评测服务，也没有购买资源包、配置密钥或上线功能**
- 背景：SpeakUp 当前的语音识别负责把录音转成文字，文本评估负责内容、语法和表达反馈。两者都不能稳定保留并判断音素、重音、音高、节奏等声学信息，需要新增专用口语评测能力。

---

## 1. 需求与能力边界

本功能真正需要的是四类可结构化返回的信号：

1. 单词和音素准确度：能定位是哪个词、哪个音素需要改。
2. 词重音：能区分标准重音位置和用户实际重音位置。
3. 流利度与韵律：能识别不自然停顿、语速、节奏、语调、连读和弱读等问题。
4. 可解释结果：至少包含单词时间戳、参考音素、检测音素和分数，供产品生成精简的教学反馈。

需要先区分两种场景：

- **有参考文本**：用户跟读指定单词或句子。系统知道用户本来应该说什么，最适合做音素和重音诊断。
- **自由表达**：用户自行回答问题。系统可以根据识别文本评估“这些词说得是否清楚”，但无法仅凭声音确定用户心里原本想说哪个词。

以 `sailor` /ˈseɪlər/ 和 `seller` /ˈsɛlər/ 为例，核心差异是第一音节的 /eɪ/ 与 /ɛ/：

- 已知目标词是 `sailor` 时，专用引擎可以判断用户是否把 /eɪ/ 说得更接近 /ɛ/。
- 完全自由说时，如果系统不知道用户想表达“水手”还是“卖家”，任何引擎都不能把语义意图当成声学事实。此时只能根据题目语境提出候选，或让用户确认目标词后重新评测。

## 2. 腾讯云口语评测（新版）：首选试点方案

### 2.1 产品状态纠正

此前文档将“基础版停止迭代”误写成了腾讯云口语评测整体入口和新版能力不可确认。该结论已过时。

截至 2026-08-23，腾讯云公开提供并持续维护：

- [口语评测（新版）文档入口](https://cloud.tencent.com/document/product/1774)
- [新版评测模式介绍](https://cloud.tencent.com/document/product/1774/107373)
- [新版 WebSocket API](https://cloud.tencent.com/document/product/1774/107497)
- [新版 Python SDK](https://cloud.tencent.com/document/product/1774/107360)
- [新版计费概述](https://cloud.tencent.com/document/product/1774/107342)

[口语评测（基础版）产品页](https://cloud.tencent.com/product/oeb)确实写明基础版已停止迭代并将下线，但同时明确推荐使用口语评测（新版）。因此应评估和接入产品编号 `1774` 的新版，而不是继续依赖产品编号 `884` 的基础版接口。

### 2.2 已确认能力

新版支持中文普通话和英语，包含以下主要模式：

| `eval_mode` | 模式 | SpeakUp 可能用途 |
|---|---|---|
| 0 | 单词评测 | 指定词跟读 |
| 1 | 句子评测 | 有参考句的整句评测 |
| 2 | 段落评测 | 较长回答的整体评测 |
| 3 | 自由说评测 | 无预设文本的整体清晰度和流利度 |
| 4 | 单词音素纠错 | 对低分词做二次音素与重音诊断 |
| 5/6 | 情景、多分支评测 | 有候选答案或关键词的练习 |

[单词纠错评测模式](https://cloud.tencent.com/document/product/1774/107390)公开返回：

- `Words.PronAccuracy`：单词准确度
- `Words.PronFluency`：单词流利度
- `Words.PhoneInfos.PronAccuracy`：音素准确度
- `Words.PhoneInfos.Phone`：从音频检测出的音素
- `Words.PhoneInfos.ReferencePhone`：参考音素
- `Words.PhoneInfos.Stress`：参考音素是否应重读
- `Words.PhoneInfos.DetectedStress`：用户是否实际重读
- `MemBeginTime` / `MemEndTime`：单词、音素在音频中的位置

它还支持：

- [音素到国际音标转换和指定国际音标](https://cloud.tencent.com/document/product/1774/107386)
- [句子模式的指定发音、音素和字母映射](https://cloud.tencent.com/document/product/1774/107387)
- 自定义人名、地名、生僻词和未登录词发音
- `ScoreCoeff` 1.0–4.0 的评分苛刻度调节

[评测维度说明](https://cloud.tencent.com/document/product/1774/107384)明确写明：

- 准确度综合考虑元音、辅音、音节、单词重音和句子重音。
- 流利度综合考虑连读、失去爆破、弱读、同化、意群与停顿、语调和节奏。
- 完整度根据识别文本与参考文本的匹配比例计算。

因此腾讯云新版能够覆盖本次提出的音素、重音、流利度和近音词目标词诊断需求。

### 2.3 API 与接入复杂度

- 协议：`wss://soe.cloud.tencent.com/soe/api/` WebSocket。
- 鉴权：新版文档规定使用 AppID、SecretID、SecretKey 生成 HMAC-SHA1 签名；不能沿用基础版 TC3 HTTP 接口的假设。
- 音频：16kHz、16bit、单声道，支持 PCM、WAV、MP3、Speex。
- 返回：JSON，可在发送音频期间返回中间结果和最终结果。
- 默认并发：50 路。
- 服务端 SDK：Python、Java、Go 均有官方示例。
- 录音模式：可一次性发送最长 60 秒音频；更长内容应按模式限制采用流式或分段策略。

对 SpeakUp，建议只在服务端签名和调用，不把长期密钥放到浏览器。实现前还应重新核对当前录音转码的采样率、位深和声道；不能只根据历史配置推断现状。

### 2.4 最新价格

新版中英文合并计费、资源共享，与旧基础版中英文分开计费不同。

| 计费方式 | 官方价格 |
|---|---|
| 首个体验资源包 | 1 万次 / 1 年，9.9 元，仅可购买一次 |
| 15 万次资源包 | 600 元 / 年，即 0.004 元/次 |
| 100 万次资源包 | 3,750 元 / 年，即 0.00375 元/次 |
| 500 万次资源包 | 17,500 元 / 年，即 0.0035 元/次 |
| 后付费 | 0.005 元/次，即 5 元/千次 |
| 额外并发 | 30 元/个/月；前 50 路免费 |

段落和自由说模式按参考文本长度折算，不超过 20 个单词计 1 次，超过后每 20 个单词计 1 次并向上取整。单词和句子评测按评测调用计费。

按后付费粗略估算：

- 一次句子评测，再对 3 个低分词做单词纠错：约 4 个计费单位，即 0.02 元。
- 一次 21–40 词的自由说评测，再对 3 个低分词做单词纠错：约 5 个计费单位，即 0.025 元。

以上只是按公开计费规则推算，不含失败重试、额外分段和未来价格变化。

### 2.5 数据合规

[腾讯云语音识别服务条款](https://cloud.tencent.com/document/product/301/94121)已明确覆盖口语评测，并说明：

- 本服务的数据处理地点为中华人民共和国境内。
- 数据只在提供服务所必需的期间保留，处理结束后按约定停止使用、返还或删除。
- 腾讯云可能根据委托和服务需要让关联方或合作伙伴参与数据处理。
- 产品方仍需确保音频收集合法，并完成告知、同意和必要的数据保护义务。

这使其比默认调用境外区域更适合作为中国大陆用户的首选，但不代表 SpeakUp 可以省略隐私政策更新、麦克风授权说明、第三方处理披露和删除机制。

### 2.6 已知限制

- 官方接口能力不等于真实教学效果，尤其是中国母语者、不同英语水平和手机噪声环境下的误报率，必须实测。
- 自由说模式能评测发音清晰度和流利度，但无法可靠推断用户未表达出来的语义意图。
- 文档未提供一个统一的 en-US/en-GB 口音切换参数；可通过指定发音或国际音标控制目标词，但需要产品层明确目标口音策略。
- 近音词“二选一”不是公开的专用返回字段。已知目标词时直接评测有效；未知目标词若采用同一片段分别对多个候选打分，是否可横向比较必须通过试点验证，不能先假设分数天然可比。

## 3. 其他主流收费方案

### 3.1 Azure Speech Pronunciation Assessment：中国区质量对照组

官方资料：

- [发音评估使用说明](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/how-to-pronunciation-assessment)
- [中国区发音评估说明](https://docs.azure.cn/zh-cn/ai-services/speech-service/how-to-pronunciation-assessment)
- [Azure 中国区价格](https://www.azure.cn/pricing/details/cognitive-services/index.html)
- [主权云支持范围](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/sovereign-clouds)
- [Speech 数据隐私说明](https://learn.microsoft.com/en-us/azure/ai-foundry/responsible-ai/speech-service/speech-to-text/data-privacy-security)

已确认能力：

- 全文、单词、音节和音素四层准确度。
- `AccuracyScore`、`FluencyScore`、`CompletenessScore` 和 `ProsodyScore`。
- Prosody 涵盖重音、语调、语速和节奏，并可返回意外停顿、缺失停顿、单调等反馈。
- 支持有参考文本的 scripted 模式和无参考文本的 unscripted 模式。
- 可用 Speech SDK 做流式或连续评测，也有短音频 REST API；旧文档中“只能使用 SDK”的结论不准确。
- 世纪互联运营的 Azure 中国区已公开列出 Pronunciation Assessment，区域包括 China East 2、China North 2、China North 3。此前“Azure 中国区可用性未确认”的结论已过时。

限制：

- Prosody 当前只对 `en-US` 提供完整支持。
- 无参考文本模式的识别模型与普通 Azure STT 不同；官方建议需要高准确文本时先做 STT，再以该文本进行 scripted 评测。
- 官方没有像 Speechace 那样公开“多个候选词中选择最接近一个”的专用接口。

Azure 中国区含税价格：

- 标准实时语音转文本：3 元/音频小时。
- 发音评估的 Prosody、语法、词汇、主题等增强能力：3.05 元/小时/功能。
- 若使用基础发音评分加 Prosody，可按约 6.05 元/音频小时估算；30 秒约 0.0504 元，1 分钟约 0.1008 元。
- 免费层含每月 5 小时标准语音转文本，但不能据此假设所有增强项都免费。

合规方面，官方说明实时发音评测不会保留客户提供的音频和文本，并且 Speech 数据在资源创建区域内处理。若采用 Azure，应使用世纪互联中国区资源，而不是默认把大陆用户音频发往全球区域。

- Basic 版支持 Multiple Choice Voice Activities，可把 `sailor` 和 `seller` 作为候选，返回声音更接近哪个目标。这是几家方案中最明确的近音词候选能力。

### 3.4 普通 ASR 不是发音评测替代品

- [Google Cloud Speech-to-Text V2](https://docs.cloud.google.com/speech-to-text/docs/reference/rest/v2/projects.locations.recognizers)公开的词级能力是识别文本、时间戳和识别置信度，没有音素准确度、词重音或韵律评分。
- [Amazon Transcribe Item](https://docs.aws.amazon.com/transcribe/latest/APIReference/API_streaming_Item.html)中的 `PRONUNCIATION` 只是表示该 token 是“口语单词”而不是标点，不是发音质量得分。
- 阿里云和百度的公开语音产品文档中，截至本轮调研未发现与上述专用口语评测引擎等价的公开结构化音素评分接口。由于“未检索到”不等于永久不存在，后续若厂商新增产品应重新核查，不能把本结论写成绝对不存在。

## 5. 大模型在本功能中的正确角色

### 5.1 不能独立承担评分

- 文本大模型只看到 ASR 转写，声音中的音素、音高、重音、停顿和节奏已经丢失。
- 普通 ASR 会利用上下文纠正不标准发音；识别结果正确不代表发音正确。
- 音频多模态模型可以给出主观反馈，但公开产品通常没有稳定、可校准的逐音素评分契约，重复调用的一致性也需要单独验证。

因此不应让大模型直接充当生产评分器，也不应把 ASR 置信度改名为“发音分”。

### 5.2 适合承担解释层

推荐职责分工：

1. 专用口语评测引擎输出音素、重音、时间戳、流利度等结构化事实。
2. 人工维护的音素教学规则库提供可靠的口型、舌位和最小对立词练习建议。
3. 大模型只负责把结构化事实和规则整理成简短、自然的中文说明，并生成少量练习例句。

这能避免模型凭空编造“听到了哪个音素”或给出错误口型建议。

## 6. 推荐结论与拟议接入方式

### 6.1 明确推荐

1. **首选试点：腾讯云口语评测（新版）SOE-N。** 能力覆盖完整、单词纠错字段最贴合产品、费用低、境内处理，并且新版入口和价格已经公开确认。
2. **同批质量对照：Azure 中国区。** 它的 Prosody 维度清晰，可作为韵律和停顿质量上限的对照，不再需要默认走境外区域。
3. **国内备选：讯飞。** 如果腾讯云在真实中文母语者录音上的误报较高，或韵律字段不够用，再验证 ISE/Suntone。
4. **专项对照：Speechace Pro。** 仅在允许境外处理的测试数据上评估其词重音和近音词候选能力，不作为默认生产路径。

本结论是“先试腾讯，再用同一批真人录音对比”，不是在没有真实评测结果的情况下直接锁定供应商。

### 6.2 拟议架构，尚未实现

```text
用户录音
  ├─ 现有 ASR → 用户说了什么
  └─ 发音评测任务
       1. 用 ASR 转写作为句子/段落参考文本
       2. 获得整体准确度、流利度、完整度和单词时间戳
       3. 选最多 3 个低分词，裁切相应音频片段
       4. 用单词纠错模式获得参考音素、检测音素和重音
       5. 结构化结果落到本次练习记录

结果页先展示现有内容
  └─ “发音”卡片异步完成后出现，不阻塞主要结果
```

产品呈现建议：

- 一次最多显示 3 个最值得改的问题，避免把整段音素数据倒给用户。
- 每个问题只保留：目标词、目标音、实际更接近的音、重音、原音片段、标准音频和“再练一次”。
- 对 `sailor` / `seller` 这类问题，只有目标词已知或用户确认意图后才下结论。
- 不展示没有行动价值的“Meaning”字段；含义和中文翻译可放进示例的展开区。
- 发音卡片失败时不影响现有结果页，允许稍后重试。

数据处理建议：

- 默认在当前请求生命周期内完成评测，不因本功能新增永久原始音频存储。
- 只持久化必要的结构化评分、问题词、音素、时间戳和供应商版本。
- 如未来为了复核确需保留音频，应先单独设计保留期限、用户删除、访问控制和隐私披露，不能顺手长期存入对象存储。
- 供应商密钥只放服务端，并使用最小权限和可轮换配置。

## 7. 试点评测方案与上线门槛

### 7.1 数据集

建议准备 200–300 条真人录音，不用 TTS 音频代替，覆盖：

- 10–15 名中文母语者，包含不同性别、年龄段和英语水平。
- 至少 30 组最小对立词：`ship/sheep`、`rice/lice`、`sailor/seller` 等。
- 词重音：名词/动词重音变化、多音节词、常见中文母语者错误。
- 句子级停顿、连读、弱读、失爆、语速过快/过慢、单调。
- 不同手机、耳机、房间混响和轻度背景噪声。
- 正确发音与错误发音都要有，避免数据集只验证“能不能挑错”。

每条录音由至少两名英语教师独立标注：目标词、错误音素、重音是否正确、整体流利度和可接受性。分歧样本经复核形成最终标签。

### 7.2 建议验收指标

以下是 SpeakUp 的建议门槛，不是任何供应商的官方保证：

| 指标 | 建议门槛 |
|---|---|
| 已知候选集合下的近音词 Top-1 准确率 | ≥ 90% |
| 词/音素问题提示精确率 | ≥ 85% |
| 词/音素问题召回率 | ≥ 75% |
| 重音位置判断准确率 | ≥ 85% |
| 整体发音/流利度与教师评分 Spearman 相关性 | ≥ 0.75 |
| 正确发音样本的误报率 | ≤ 10% |
| 评测任务 p95 附加延迟 | < 3 秒 |
| API 失败或空结果率 | < 1% |

还需分别记录：

- 每次练习的平均和 p95 计费单位。
- 安静/噪声、不同设备和不同水平用户的分组指标。
- 相同录音重复请求的分数波动。
- 供应商返回的音素与产品展示 IPA 的映射正确率。
- 对结果页主链路的延迟和失败隔离效果。

### 7.3 试点决策规则

- 腾讯云达到全部门槛：采用腾讯云作为首发供应商。
- 腾讯云音素合格但韵律不足：腾讯负责词/音素，是否增加 Azure Prosody 由成本实验决定。
- 腾讯误报不合格：先调苛刻度和音频预处理，再与 Azure 中国区、讯飞对照，不通过换提示词掩盖底层评分问题。
- 所有云方案都不合格：停止上线发音纠正，保留研究结果，不向用户展示不可信分数。

## 8. 开源与自建：远期储备

旧调研中以下资产仍有参考价值：

- [speechocean762](https://github.com/jimbozhang/speechocean762)：中文母语英语学习者朗读和人工评分数据，可用于研究句子、单词和音素级评测。
- [Montreal Forced Aligner](https://github.com/MontrealCorpusTools/Montreal-Forced-Aligner)：可生成词和音素强制对齐结果。
- wav2vec 2.0、CTC、GOP（Goodness of Pronunciation）路线：可构建自有音素打分和校准模型。

自建的优势是数据和边际成本可控，代价是需要语音算法、训练数据许可复核、人工标注、校准、GPU 推理、模型监控和持续公平性评估。当前阶段不建议把它作为首发方案；当调用量、数据规模或供应商约束足够大时，再单独立项验证。
