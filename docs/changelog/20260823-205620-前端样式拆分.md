# 前端样式拆分

- 时间：2026-08-23 20:55（北京）
- 关联 PR：#167

## 背景

前端所有主要样式长期集中在 3237 行的 `App.css` 中。现有 ESLint 只检查 JS/JSX，无法阻止 CSS 文件继续增长，也让修改局部页面样式时难以确认级联影响范围。

## 方案与权衡

- 按现有顶层章节边界把 `App.css` 机械拆成 8 个文件，由原入口按固定顺序导入；
- 不在同一次改动中删除疑似废弃选择器或重新组织规则，优先保证级联顺序不变；
- 每个拆分文件不超过 500 物理行，最大文件为 495 行；
- 新增独立 Node 检查脚本，递归扫描 `web/src/**/*.css`，500 行允许、501 行失败；
- 将检查接入 `pnpm run lint`，复用现有 CI，无需再引入样式工具依赖；
- 新增自动化测试覆盖末尾换行计数、递归扫描、忽略非 CSS 文件和超限识别。

机械切片完成时，8 个文件按顺序拼接的 SHA-256 与原文件完全一致。随后只中性化了一条旧注释，CSS 规则及其顺序没有变化。Vite 构建产出的 CSS 资源文件名也与拆分前一致。

本轮门禁只解决用户指出的 CSS 问题。JS/JSX 继续使用 ESLint 的 500 有效行规则；现有 3 个物理行超过 500 的 JS/JSX 文件如需改成严格物理行口径，应另开 PR，避免把逻辑重构混入纯样式迁移。

## 验证

- CSS 行数检查扫描 11 个文件，全部不超过 500 行；
- 门禁测试 2 项通过；
- 前端全量测试：26 个文件、282 项通过；
- 覆盖率：Statements 88.03%、Branches 81.86%、Functions 86.11%、Lines 91.66%；
- ESLint：0 error，保留 23 个既存 warning；
- Vite 生产构建通过，CSS 资源文件名与拆分前一致；
- `git diff --check` 通过；
- 独立只读复核确认切点均位于顶层规则之间，导入路径和原始级联顺序正确。

## 修复与后续

后续删除旧 CSS 前，应先结合真实页面走查和 CSS Coverage 独立处理，不要把删除与本次机械拆分混为一项。若继续推进全源码严格 500 物理行，需要先拆分既存的超长页面与测试文件，再扩大门禁范围。
