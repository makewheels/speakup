# 通知事件改成注册表驱动，并新增收藏 / 追问 / 反馈三类

- 时间：2026-09-19 22:35:55（北京）
- 关联 PR：#214

原来只有注册与练习提交两类事件，且事件类型在代码里写死：加一类要同时改 `record_*`、类型表、`_item_line` 的 if 分支和业务路由。加到五类后这种写法就难维护了。

- **解耦**：`notifier.py` 引入 `EventSpec` 注册表（标题、量词、行内字段），`build_card` 与 `_item_line` 改成数据驱动；业务侧只需调一次 `record_*`，**渲染代码不再随事件类型增长**。未注册的类型入队时被忽略并记 warning。
- **通用入口**：新增 `record_user_action(event_type, user_id, detail, ip)`，统一补昵称 / 手机号 / 来源归属地，并按账号 `sourceType` 过滤测试号。
- **三类新事件**：`review_item_added`（收藏复习，重复收藏不重复发）、`coach_question`（追问教练，带问题摘要）、`feedback_submitted`（用户反馈，带评级与评论摘要）。
- 练习提交的明细文案抽成 `attempt_detail()`（原来散在渲染函数里），标题截断逻辑随之独立成测。
- `region_of` 只对合法 IPv4 查库，IPv6 与非法值直接跳过（不再产生无意义的查询告警）。

验证：后端 447 项通过（新增 7 项：通用行为事件、测试号过滤、未注册类型、注册表渲染、三类埋点的集成断言），覆盖率 88.78% 与行数、参数门禁通过。
