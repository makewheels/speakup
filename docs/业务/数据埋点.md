# 数据埋点（Umami）

SpeakUp 使用自建 [Umami](https://umami.is) 做产品统计（无 cookie、不采集设备指纹以外的信息），部署在 services 机。采集走主域同源路径（`/umami-script.js` 与 `/api/send`、`/api/heartbeat` 由 Caddy 代理到 umami 容器，不占子域、不加 DNS）；管理后台走 `http://101.42.94.17:30040`（内部工具，HTTP 明文登录）。前端 `web/src/lib/analytics.js` 只在生产构建注入脚本，本地 dev 完全不打点。

## 事件字典

| 事件 | 触发时机 | 属性 |
|---|---|---|
| （pageview，自动） | 首次加载与 SPA 路由变化 | umami 自动 |
| `practice_recording_started` | 录音成功开始（麦克风已打开） | `mode`（scenario/free）、`userId`、`practiceId`、`sourceType`、`interactionType`、`kind`、`difficulty`、`hintCount` |
| `practice_result` | 评估完成且反馈可用 | `mode`、`score`、`gaps` 数、`round`、`userId`、`attemptId`、`practiceId`、`sourceType`、`interactionType`、`kind`、`difficulty`、`hintCount` |
| `result_shared` | 结果页分享成功（系统分享或复制链接） | `method`（shared/copied）、`userId` |
| `gap_saved` | 差距卡加入错题本成功 | `userId` |
| `note_added` | 结果文字手动摘录保存成功（重复保存不记） | `userId` |
| `followup_asked` | 追问教练发出一个问题 | `userId` |

> 渐进式场景提示（见 `8-渐进式场景练习.md`）：提示正文与录音、转写一样不上传；事件只带分层标量——`interactionType`（缺失/未知归一为 `standard`）、`hintCount`（事件时刻已显示的提示数，standard/free 恒为 0）、`practiceId`、`attemptId`、`sourceType`、`kind`、`difficulty`。`practiceId`/`attemptId` 用于与 `practiceAttempts.hintCount` 对齐。

## 隐私边界

- 只使用不透明内部 `userId`；不上传手机号、邮箱、Bearer Token、分享 token。
- 不上传录音、完整转写、笔记正文、AI 答案或请求体；事件属性只有计数/分数/模式等标量。
- 不开 Session Replay；Umami 本身无回放能力。
- 不请求浏览器地理位置权限。
- 登录态用户才产生 `userId` 属性；未登录访问者只有匿名 pageview。

## 运维

- compose：服务器 `/opt/umami/docker-compose.yml`（umami + 独立 postgres:16，数据卷 `umami-db-data`），desired-state 见 infra 仓库 `services/umami/`。
- 采集路由：Caddy `speakup.a4.fit` 块内 `/umami-script.js`（rewrite 到 `/script.js`）与命名 matcher `@umami-beacon`（`/api/send`、`/api/heartbeat`）代理到 `umami:3000`。
- 管理后台：`http://101.42.94.17:30040`（compose `ports` 暴露 + Lighthouse 防火墙放行 30040）；默认 admin 密码已在首次部署时轮换，凭据位置见 infra `inventory/secrets.md`。
- 数据库与 SpeakUp 业务 MongoDB 完全隔离；高频遥测不写业务库。
