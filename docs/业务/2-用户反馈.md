# 2. 用户反馈

> 本文档基于当前源码状态维护，描述**已实现**的行为。改动反馈相关功能时，必须同步更新本文（见 CONTRIBUTING「文档维护」）。

## 作用

收集两类反馈：

1. **练习结果反馈**（per attempt）：结果页评价「这次 AI 反馈有帮助吗」，可随时写文字，👎 还能选原因标签
2. **全局反馈**：我的页 → 反馈建议，提产品建议 / 报 bug

## 结果页反馈（FeedbackBar）

- 位置：练习结果页（`PracticeFeedbackView`）底部；历史会话回看（`SessionView`）每轮 attempt 卡片底部也有
- **文字输入框常驻**：不需要先点 👎，👍 / 👎 两种评价都可以带文字提交
- 👍 点击即提交（`rating=good`）；👎 展开原因标签（多选）后点「提交」（`rating=bad`）
- **一个 attempt 一条**：同一 `userId + practiceId + attemptIndex` upsert 覆盖，再次打开该轮会回显上次反馈，可点「修改」重选
- 提交时带当轮 AI 反馈快照（score / summary / nativeVersion / gaps / transcript / round），事后排查不依赖 attempt 还在
- 原因标签（与后端 `PRACTICE_TAGS` 对应）：`score_too_strict` / `score_too_loose` / `gap_wrong` / `native_unnatural` / `transcript_wrong` / `summary_bad`

## 全局反馈（FeedbackPage，路由 /me/feedback）

- 入口：我的页（ProfilePage）→「反馈建议」
- 标签多选（与后端 `GENERAL_TAGS` 对应）：`product` / `scenario` / `asr` / `bug` / `other` + 文字输入
- 不去重：每次提交新建一条
- 提交成功显示感谢页；标签和文字至少填一项才能提交

## API

| 路由 | 方法 | 说明 |
|------|------|------|
| `/api/feedbacks` | POST | `type: practice \| general`；practice 按 attempt upsert，general 每次新建；均需登录 |
| `/api/feedbacks` | GET | 查自己的反馈，可用 `practiceId` + `attemptIndex` 精确取某一轮 |

## 数据

`feedbacks` 集合，字段见 [design/schema.md](../design/schema.md)。导出脚本默认排除 `sourceType=ai_test` 的测试数据。
