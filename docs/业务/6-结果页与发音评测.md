# 结果页与发音评测

## 当前用户流程

用户提交转写文本后立即进入结果页，不在录音页等待完整 JSON。结果页第一块始终是固定高度的 IELTS 分数区：生成期间显示 `– / 9.0` 占位，文字反馈完成后原位替换为真实分数，下面的题目和反馈不因分数到达而整体换位。结果页只在首帧绘制前回到顶部；文字流完成、图片/视频加载和发音结果到达都不会再次改变滚动位置。

正式结果按以下层级展示：

1. IELTS 分数、轮次与一句话总结；
2. 当前模式和场景/自由说题目；
3. 「表达建议」：`gaps[]` 是唯一纠正主体，最多 3 条；
4. 「发音建议」：有本轮原声且生产开关启用时出现；
5. 可折叠的独立标准答案；
6. 追问教练、结果反馈按钮和下一步操作；
7. 「分享本次结果」作为结果页最后一个区块。

当前轮次只在顶部 IELTS 分数区下方展示。底部重试按钮固定写「Say it again / 再说一遍」，不重复显示下一次尝试编号。

`nativeVersion` 与 `sentenceCorrections` 不再由新纠正结果生成或展示。每条 gap 可以覆盖一个短语，也可以覆盖整句话：

- `original` 必须是学习者原话中的连续片段；只有完全漏说的任务信息允许为空；
- `better` 与 `original` 保持相同表达范围，保留原意；
- 同一句内相关的语法、搭配和自然度问题尽量合并成一条整句建议；
- 卡片上方展示「你说的」，下方展示「这样说」，按语义范围配对，不做字符长度对齐。
- 例句不是纠正内容的翻译或复述：只有能把同一表达规律迁移到另一个真实语境时，才显示折叠的「另一个例句」及其中文翻译；没有额外教学价值就整块不显示。

所有一级区块统一使用同一标题字号、字重和间距。标准答案的播放按钮位于 `summary` 外部，播放不会触发折叠。结果反馈默认只显示按钮，用户点击后才展开文字框、赞踩和原因标签；提交后自动收起。

自动加入复习的结果只通过对应卡片上的「已加入 / In Review」按钮状态表达；结果页不再额外显示数量和移除操作说明。用户再次点击该卡片按钮即可取消收录。

## 发音评测时序

1. 文字纠正完成并写入 attempt；
2. 浏览器上传本轮原声，服务端把 `recordingKey` 关联到 attempt；
3. 上传响应的 `pronunciationEnabled=true` 时，浏览器调用 `POST /api/practice-sessions/{id}/attempts/{n}/pronunciation`；
4. 服务端从私有 OSS 读取录音，转为 16kHz、16bit、mono WAV；
5. 腾讯句子或段落模式返回总分、逐词分和时间戳，服务端最多选 3 个低分词；
6. 低分词按时间戳裁片，再以单词音标模式取得实际/参考音素和重音；
7. 规范化结果写回 `attempt.pronunciation` 并更新当前结果页。

供应商接口使用 WSS，但浏览器仍只接收最终业务 JSON。供应商密钥和原始协议都留在服务端，供应商失败也不影响已经完成的文字反馈。

总分优先使用腾讯返回的 `SuggestedScore`；`PronAccuracy`、`PronFluency` 与 `PronCompletion` 分别规范化为准确度、流利度和完整度。

## 发音卡信息层级

发音卡最多展示 3 个行动价值最高的词：

1. 词与词级得分；
2. 用户实际 IPA → 目标 IPA；
3. 有差异的实际音素 → 目标音素，以及重音提示；
4. 一句由结构化事实确定性生成的短建议；
5. 按时间戳播放用户原音片段，并用现有 TTS 播放标准词音。

没有低分词时只显示整体分和简短通过提示。首版不放没有完整复测闭环的「再练一次」按钮。

## 生产配置与安全边界

- 生产当前启用 `PRONUNCIATION_ENABLED=true`、`PRONUNCIATION_PROVIDER=tencent`；
- 使用无控制台登录能力的独立服务身份 `speakup-pronunciation`；
- 自定义策略只授予 `soe:SpeakingAssessmentStream`，不授予控制台、购买或其他云资源权限；
- 凭据只保存在生产密钥系统，代码库和浏览器均拿不到；
- 未配置或显式关闭时，录音上传返回 `pronunciationEnabled=false`；
- 原始录音沿用既有 OSS 对象，不为评测额外永久保存一份。

一次完整评测包含 1 次句子/段落评测和最多 3 次低分词复评。腾讯按产品规则计量，后付费调用量可在控制台查看。

## 供应商结论

当前直接使用腾讯云口语评测（新版）：现有适配器已用真实 WSS 请求跑通，音素、重音、时间戳和总分字段能支持当前卡片，且本轮目标是尽快上线真实体验。

阿里云仍是首要替代方案，因为 SpeakUp 已使用阿里系基础设施，统一供应商有运维优势；但不为“统一”而在没有同批真实录音证据时立即迁移。后续只有腾讯在真实用户录音上出现明显误报、延迟、稳定性或成本问题时，再用同批录音做小规模对照并决定是否切换。详细资料见 `docs/评测/发音纠正选型调研.md`。
