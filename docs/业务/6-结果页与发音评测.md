# 结果页与发音评测

## 当前用户流程

用户提交转写文本后立即进入结果页，不再留在录音页等待完整 JSON。结果页先显示题目、轮次、「你说的」原句和纠正版生成状态；流式纠正完成后原地替换为正式结果。

纠正模型按服务端切出的源句返回 `sentenceCorrections[]`：

- `sourceId` 对应输入时的稳定句子编号；
- `original` 由服务端使用对应源句，不能信任模型自行改写；
- `corrected` 可更长、更短或拆成两句，但不能跨 `sourceId` 合并；
- 旧 attempt 没有该字段时，前端用整段 `transcript → nativeVersion` 作为一个兼容组。

页面把每组「你说的」放上方、「纠正版」放下方，不做字符长度对齐。独立标准答案和详细 gaps 默认折叠，避免结果页随着发音反馈加入后过长。

## 发音评测时序

1. 文字纠正完成并写入 attempt；
2. 浏览器上传本轮原声，服务端把 `recordingKey` 关联到 attempt；
3. 上传响应的 `pronunciationEnabled=true` 时，浏览器调用 `POST /api/practice-sessions/{id}/attempts/{n}/pronunciation`；
4. 服务端从私有 OSS 读取已有录音，转为 16kHz/16bit/mono WAV；
5. 腾讯句子/段落模式先返回逐词分与时间戳，服务端只选最多 3 个低分词；
6. 低分词按时间戳裁片，再用模式 4 返回实际/参考 IPA、实际/参考重音；
7. 规范化结果写回 `attempt.pronunciation` 并更新当前结果页。

供应商虽然使用 WebSocket，浏览器仍只拿最终业务 JSON。这样不会暴露供应商密钥，也不会让供应商的原始分片协议侵入页面状态；发音请求失败不影响已经完成的文字纠正。

## 发音卡信息层级

发音卡最多展示 3 个行动价值最高的词：

1. 词与词级得分（分数是次要信息）；
2. 用户实际 IPA → 目标 IPA；
3. 有差异的实际音素 → 目标音素，以及重音提示；
4. 一句由结构化事实确定性生成的短建议；
5. 按时间戳播放用户这个词，及用现有 TTS 播放标准词音。

首版不放没有完整闭环的「再练一次」按钮。后续只有在单词录音、模式 0 复测、通过阈值和练习记录能一起上线时才加入。

## 配置与降级

- `PRONUNCIATION_ENABLED=false` 是默认值；
- 首版 `PRONUNCIATION_PROVIDER=tencent`，密钥只在服务端；
- 缺少开关或任何凭据时，录音上传返回 `pronunciationEnabled=false`，浏览器不请求评测；
- 评测过程中显示紧凑加载卡；失败时提示本次不可用，但保留所有文字结果；
- 原始录音沿用既有 OSS 对象，不为评测再永久保存一份。

## 供应商边界

首版选腾讯是因为它的模式 4 在同一公开契约里直接返回实际/参考音素、实际/参考重音与时间戳，最贴合卡片。阿里云已有正式口语评测产品，价格和现有供应商统一性更好，是首要备选；同批真人录音 A/B 若质量和字段稳定性相当，应优先切回阿里云。详细证据见 `docs/评测/发音纠正选型调研.md`。
