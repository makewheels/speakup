# SpeakUp 微信小程序版本计划

状态：待设计（2026-10-16）。已记录产品范围、实施顺序和验收要求，尚未开始小程序实现。

## 背景与问题

用户希望 SpeakUp 增加小程序版本，方便在微信内随时练口语、查看反馈和回顾练习。本文按微信小程序规划；其他小程序平台后续另行评估。

现有 React Web 依赖浏览器录音、fetch 流式读取、localStorage 与浏览器路由，不能直接搬成小程序。后端现有场景、Attempt、反馈和复习数据应继续共用，避免建立另一套题库和练习记录。

## 目标与非目标

**首版最低要求：小程序具备网页端全部现有用户功能，业务行为和数据一致，不交付功能裁剪版。** 学习闭环和同账号互通只是其中一部分，不能代替全功能验收。

**服务端目标：优先采用云函数及配套托管服务，使用户无需购买、部署或维护常驻服务器。** 选型、流式语音链路和成本通过技术验证确定；这不是已完成的部署承诺。

- 题库、偏好、练习会话、Attempt、录音、反馈、复习项共用现有服务端模型与业务接口。
- 支持中文和英文界面、无图场景、权限拒绝、弱网与音频服务失败时的可恢复体验。
- 分享可打开指定练习结果，取消分享后原入口失效；只有公开分享接口允许匿名读取。
- 保留现有 Web，两个客户端分别构建和发布。

不额外新增网页尚未实现的实时语音对话、支付、订阅消息等业务。[实时语音探索](20260920-实时语音对话探索.md)独立推进；若其在小程序验收前成为网页正式功能，也要纳入对照。界面可适配小程序交互习惯，但不得以平台差异为由取消用户能力；确有技术障碍时先研究等价方案并记录缺口，未解决不得宣称功能对齐。

## 当前代码依据

| 位置 | 已有能力与迁移影响 |
|---|---|
| `web/src/api/client.js` | JSON、multipart、Bearer 鉴权，以及评估/追问两套 SSE 消费；需要小程序网络适配 |
| `web/src/context/UserContext.jsx` | 登录和偏好缓存；小程序需改用自己的存储及生命周期 |
| `server/routes/auth.py`、`server/services/auth_tokens.py` | 手机号入口创建业务会话，令牌摘要保存在 `authSessions`，业务接口验证 Bearer；目前手机号入口缺少号码归属验证 |
| `server/routes/transcribe.py` | multipart `audio/userId/practiceId`，检查登录用户一致性和 30MB 上限；实际录音格式仍需逐端验证 |
| `server/routes/correct.py` | 已有同步评估和 SSE；流式包含 `started/chunk/reset/done/error`，必须保留 Attempt 关联及服务切换重置语义 |
| `docs/design/schema.md`、`docs/业务/` | 业务数据与已实现行为的依据；新增微信身份映射后同步设计，不在本文假定已经落地 |

以上来自当前代码。入口文档仍有“无 token”的历史描述，实施时以代码和接口测试核对后同步修正。

## 方案权衡与暂定方向

| 方案 | 权衡 | 暂定决定 |
|---|---|---|
| Web 页面放入 web-view | 页面改造少，但录音、登录、分享与平台配置仍需验证 | 不作为首版主方案 |
| 原生微信小程序 + TypeScript | 可直接控制录音、网络、音频和生命周期，页面需要重写 | 优先方向，技术验证通过后定案 |
| 跨端框架 | 可能复用部分开发经验，但不能直接复用现有 DOM/CSS/浏览器能力，新增框架维护成本 | 仅当技术验证证明收益时采用 |

暂定新增 `miniprogram/` 客户端，复用现有业务规则、数据及 AI 服务；现有 FastAPI/MongoDB/OSS 是迁移依据，服务端最终部署按下节托管方案验证。先复用接口契约和纯数据逻辑，避免为抽共享库提前大改 Web。Node 依赖用 pnpm，共用全局 store；Python 依赖继续用 uv。

### 服务端：云函数与托管服务

- 优先调查阿里云 FC，北京区域作为默认候选；普通 API 不绑定现有 Docker/Caddy/SSH 部署。是否使用 FastAPI 适配入口由实际验证决定，业务逻辑与运行平台分离。
- 数据库同样必须有无需自管服务器的方案。现有 MongoDB 作为兼容基线，调查托管数据库的兼容性、网络、连接池、索引、备份和费用；不能只迁 API、仍要求用户维护数据库主机。保留历史用户、练习、Attempt、复习、分享及鉴权数据，不直接假定换连接串即可迁移。
- 录音、头像、反馈图片和缓存音频进入托管对象存储；签名、权限、跨端读写、上传下载限制逐项验证，私钥和供应商凭据只在服务端取用。
- 派题生成、定制题、通知、语音/评估等后台工作盘点进程内任务、定时器和长连接，改用合适的托管异步/定时触发及持久任务状态；覆盖重复、超时、进程退出、部分成功与恢复，不依赖常驻工作进程。
- SSE/流式追问、录音上传、ASR/TTS的正文大小、执行时间、代理缓冲、连接中断和冷启动都要真机加真实云入口验证。改传输方式可以，不能因此丢掉网页的流式反馈、追问或失败恢复能力。
- 网页与小程序共用同一业务服务及数据，不维护功能分叉。设计现有网页到新入口的兼容迁移与回退；切换前保留旧部署，实际验收和在途工作交接完成后才能退役。
- 发布通过 Git 与 CI，配置/取密、日志、告警、域名、备份恢复均使用托管方案；发布及运行都不能回到原服务器取配置、转发请求或执行任务。
- 普通请求空闲时不靠保活维持实例；托管数据库、存储、网络与调用可能仍产生费用。先比较实测成本、最低消费及运维负担，再决定具体产品与规格，不把“无需自管服务器”写成“免费”。
- 本次只记录方向，不购买资源、不迁移数据库、不切生产或删除旧服务器。需要新增付费资源或生产迁移时，先形成具体可审阅方案。

### 登录与老账号

- 新增微信 code 的服务端交换入口，由服务端确认微信身份后签发现有业务 Bearer 会话；客户端提交的 openid 不作为身份凭据。
- 微信身份映射到现有 `userId`，不把 openid 直接当业务用户 ID；AppSecret、供应商密钥与微信会话密钥均留在服务端配置。
- 老账号关联必须验证号码或既有可信会话的控制权，不能只输入手机号就合并历史数据。具体绑定方式在第一阶段设计并测试；不因开发方便自动合并两个用户。
- 授权取消、会话失效、重复绑定、账号冲突和退出登录均有明确行为；小程序凭据与 Web 存储隔离。
- 当前手机号直接登录的既有风险是公开上线前待解决项，新增微信登录本身不能消除它；限制或升级旧入口须单独设计兼容方式。

### 录音、播放与流式反馈

- 通过小程序录音 API 实现开始、停止、试听和重录；先实测 iOS/Android 的编码、MIME、文件大小和后端转写兼容，再固定格式与时长限制。
- 录音上传复用现有 multipart 接口，并与服务端返回的 `attemptId` 关联；离开页面、来电或切后台后停止采集，保留可恢复提示，释放音频资源。
- TTS 复用后端返回音频地址及缓存；签名过期重新取得地址。小程序不依赖浏览器 `speechSynthesis`，朗读失败时保留文字并允许重试。
- 首选验证分块请求消费现有 SSE，覆盖 UTF-8 跨块、半帧、多帧、`reset`、取消、超时及断连。不能假设开发工具成功等于真机成功。
- 如果分块链路不可靠，先验证已有同步评估作为降级的完成时间和结果一致性；追问另定可恢复方案。断线后优先按会话/Attempt 查回结果，不能自动重复提交产生新轮次和收费调用。

## 全功能对照范围

以网页当前路由、页面、组件、接口及实际行为共同建立清单；下表是起始范围，不是允许遗漏未列功能的白名单。M0记录基准提交，实施期间跟踪网页新增/变更，发布前重新核对最新基准。每项记录网页入口、小程序入口、行为/数据、异常场景、测试和真机证据。

| 网页功能 | 小程序最低对齐范围 |
|---|---|
| 登录与引导 | 同一业务账号、登录后回原目标、会话失效、退出及旧账号关联；微信登录是平台适配 |
| 场景练习 | 全部现有练习模式、指定题、偏好、渐进提示、换题、无图题、录音/试听/重录、手动输入与转写修正 |
| 自由说 | 话题抽取/切换、去重、录音建会话、评估与重练，和网页相同 |
| 结果与追问 | summary、gaps、进步对比、标准答案/重点表达、例句、朗读、流式追问、复制与选词/收藏笔记等网页现有操作 |
| 历史与详情 | 全部现有列表/分页、各轮Attempt恢复、原声回放和再次进入结果 |
| 错题本与笔记 | 错题/好表达、翻译、复习、记住/未记住、收纳/恢复、删除和用表达练题等现有操作 |
| 个人资料与设置 | 昵称、头像上传/更换/恢复默认、练习偏好、语言和主题（跟随系统/浅色/深色） |
| 用户反馈 | 结果页赞踩/标签/文字、多图原件上传、全局反馈及网页已有提交记录/状态 |
| 分享与管理 | 开启/取消分享、分享管理、公开详情、复制/转发、冷启动直达和登录后回原目标 |
| 共同行为 | 加载/空/错误/重试、权限、弱网、页面重进恢复、双语与跨端数据同步 |

自由说、头像修改、多图反馈均在首版必交付范围。默认关闭的场景生图等配置沿用网页规则，不为小程序单独减少功能。截图逐像素相同不是要求，用户可完成的操作、结果、权限和异常恢复必须等价。

## 分阶段实施 checklist

### M0：全功能盘点、平台与云端技术验证

- [ ] 从网页最新基准建立逐功能/子操作清单，覆盖所有路由、组件交互及异常路径；首版范围不留“后续补齐”。
- [ ] 盘点服务器依赖，形成云函数、托管数据库、对象存储、异步任务、定时触发、日志告警和CI发布方案，比较兼容性、成本及迁移回退。
- [ ] 真正云入口验证冷/热请求、流式反馈、语音上传/转写/播放、数据库连接和失败恢复；本地启动不代替云端验证。
- [ ] 确认小程序主体、AppID、可用类目、隐私申报与当前审核要求；域名/上传下载域名等在平台后台配置，不把实际地址和凭据写进仓库。
- [ ] 真机验证录音 → 上传 → ASR、TTS 播放、SSE 分块和分享入站；记录微信/系统/基础库版本、配置、失败样本与实际耗时。
- [ ] 核对服务端超时、代理缓冲、签名地址和跳转后的对象存储访问；开发工具关闭域名校验不算通过。
- [ ] 依据验证结果确定原生或跨端方案、最低基础库、同步降级边界及账号绑定协议。

### M1：项目骨架与账号

- [ ] 建立客户端工程、配置模板、双语字典、网络/上传/音频/存储适配和独立 CI。
- [ ] 完成微信登录、业务令牌复用、身份映射与老账号绑定；覆盖越权、伪造身份、冲突和重复请求。
- [ ] 区分开发/体验/正式环境；补服务端测试、模型说明及配置文档，不直接迁移现有数据。
- [ ] 建立云函数部署与取密、托管数据访问及可追溯发布/回退，不新增自管常驻服务。

### M2：练习和反馈闭环

- [ ] 接通场景和自由说全部模式、偏好、提示、会话创建、录音转写、手动输入、文本修正和评估。
- [ ] 接通标准答案、差距反馈、TTS、追问、重练及 Attempt 录音关联。
- [ ] 页面参数保存必要业务 ID，冷启动/重进可从服务端恢复；提交中断、重复点击和流式重置无重复结果。

### M3：补齐全部网页功能

- [ ] 接通历史、详情、复习项和收藏表达；与 Web 的同账号数据双向核对。
- [ ] 实现分享路径、匿名只读、取消分享失效、登录后返回原目标；分享参数不携带私人令牌。
- [ ] 完成昵称、头像上传/恢复默认、语言、主题和偏好。
- [ ] 完成结果反馈与全局反馈、多图上传、记录/状态，以及结果页表达讲解、复制/收藏等网页全部子操作。
- [ ] 按M0清单逐项消除差异；阶段只划分实施顺序，不代表允许裁剪发布。

### M4：真机验收与发布准备

- [ ] 对网页最新基准逐项全量验收，覆盖所有用户功能和子操作；缺项不得作为首版发布。记录真机证据、已知问题和后端/Web回归结果。
- [ ] 验证完整运行链路无需自管服务器，完成托管数据备份恢复、异步故障恢复、费用评估及旧服务切换/回退演练；未验收前不退役原服务。
- [ ] 完成平台当前要求的隐私说明、录音用途与权限文案，体验版验收后再提审；主体资格和审核材料以平台实际要求为准。
- [ ] 固定客户端版本、后端最低兼容版本、发布顺序与回退步骤；小程序审核周期内旧客户端仍可访问兼容 API。
- [ ] 实施完成后同步设计/业务/变更档案，再更新本需求状态。只有计划提交不能勾选这些实施项。

## 验收标准

| 范围 | 通过条件 |
|---|---|
| 全功能一致 | 网页功能/子操作清单全部逐项通过；自由说、头像、多图反馈、主题等均不可延期；技术缺口未解决不得标完成 |
| 无需自管服务器 | API、数据库、文件、后台任务、调度、配置及运行依赖全部有已验证托管方案；生产入口不依赖原常驻主机，保留数据并通过迁移/回退验收 |
| 学习闭环 | 两类真机均完成一题、查看反馈、重练和复习；无图题可正常练习 |
| 账号 | Web 老用户成功关联且历史不丢；不同用户不能读取私人记录或绑定他人账号；公开分享仅暴露原允许字段 |
| 录音 | 首次允许/拒绝、再次授权、静音、切后台、来电、重录和上传失败均可恢复；原声归属正确 Attempt |
| 反馈 | chunk/reset/done 顺序、跨块中文与错误正确处理；断线重进可恢复已保存结果，无隐式重复评估 |
| 音频 | 标准答案和录音可播，播放互斥；签名过期可重新取址；TTS 失败保留文本 |
| 数据互通 | Web 创建的历史/复习在小程序可见，反向也成立；偏好使用同一服务端事实源 |
| 分享 | 冷启动直达目标；匿名与已登录行为正确；取消分享后失效，非法参数有可返回页面 |
| 质量 | 客户端关键状态测试、后端鉴权/绑定/接口回归、Web 既有测试通过；开发工具和真机分别记录，skipped 不记为通过 |
| 成本与发布 | 测试使用专用测试账号、默认 mock 外部服务；真实语音小样本记账，无因重试重复调用；审核与兼容回退均有实际记录 |

性能指标先由 M0 测量录音上传、转写、首段反馈、完整评估和播放启动，再确定可接受阈值；本计划不编造耗时或工期承诺。
