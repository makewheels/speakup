# 实时语音对话探索

状态：待设计（2026-09-20 记录，暂不实施）

## 背景与问题

练口语的核心是真实对话，但现有链路是独白式：看题 → 录音 → 转写 → 文本评估 → 朗读反馈 + 文字追问。
用户练不到对话能力：听懂对方、实时组织语言、被追问、应对突发。

百炼已有实时语音对话模型（首选 `qwen3.5-omni-flash-realtime`，备选 `qwen3-omni-flash-realtime`），
全双工、可打断、自带流式转写、支持 instructions 角色设定。技术上第一次可以把"独白练习"
还原成"真实互动"：题库 16 大类 67 子场景里 task / chat 类占 64%，本来就全是双人互动戏。

## 目标与非目标

目标：

- 新增"实时语音对话"练习形态，作为现有独白练习之外的第二形态。
- 对话必须"有教学"：每场有结构化诊断、有沉淀、能重练；复用现有场景库、定制题、corrector 复盘与复习项。

非目标：

- 不做自由聊天／通用陪聊。通用助手已提供免费实时语音陪聊且语音质量顶级，硬碰无胜算；
  差异只能建立在教学法 + 用户数据 + 题库编排上——"有教学的对话"，不是"对话式的聊天"。
- 不替换现有录音链路，保留作降级通道。

## 方案权衡

| 方案 | 结论 |
|---|---|
| 替换现有录音链路 | 否。现链路成本低且 TTS 有内容缓存，独白模式仍有独立价值（如雅思 Part 2） |
| 新增对话形态，结束后把 transcript 喂现有 corrector 出复盘 | 选定方向。核心资产全部复用，realtime 只承担"对话"这一层 |
| 让 realtime 模型直接出结构化反馈 | 不可行，模型不支持 Function Calling 与结构化输出 |

## 技术事实（已验证）

- 定价（按百万 token）：音频输入北京约 19 元（3.5 档国际价约 34 元，北京价待控制台确认）、
  输出文本+音频约 75 元；5 分钟对话粗估 1~3 元，需 spike 实测。
- 限流 RPM 60 / TPM 100,000，约合 20 路并发对话，上线前需提配额。
- 不支持 Function Calling、结构化输出、上下文缓存；自带 `input_audio_transcription` 流式转写（可支撑实时字幕）。
- 音频参数：麦克风输入 16kHz、模型输出 24kHz。

## 后续候选（不在本轮）

- 考试模拟：雅思口语 Part 1/3 问答 + 追问（Part 2 独白保留现有模式）
- 纯语音场景：客服电话、订餐电话、预约（天然无画面，与 realtime 最对口）
- 无限陪聊入口：轻量高频模式，同样带沉淀

## 验收标准

- 一次对话练习端到端可用：开口 → 对话 → 结束后出结构化复盘与复习项，复盘质量不低于现有独白管线。
- 每分钟真实成本有实测数据；并发能力满足上线门槛（配额已提）。
- iOS Safari 与 Android Chrome 的录音、打断、回声消除实测通过。

## 风险

- 成本比现有链路高一个量级（现有：转写近乎免费 + 文本极便宜 + TTS 有缓存）。
- 移动端麦克风流与打断体验未验证。
- 通用助手能力持续变强，护城河必须在教学法与数据，不在语音管道本身。
