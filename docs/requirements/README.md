# Requirements 需求与实施记录

本目录记录尚在讨论或实施中的需求事实，回答五个问题：遇到了什么问题、目标是什么、有哪些方案权衡、最终选择什么、做到什么算完成。它是产品与开发的接力工作台，不等同于当前设计，也不等同于完成记录。

## 与其他目录的边界

| 目录 | 回答的问题 | 是否记录进度 |
|---|---|---|
| `requirements/` | 为什么要做、要做什么、如何验收、现在做到哪 | 是 |
| `design/` | 当前确定的数据结构、架构、交互和长期约束是什么 | 否 |
| `业务/` | 线上当前实际行为是什么 | 否 |
| `changelog/` | 哪次提交已经完成了什么 | 只记录完成事实 |

## 文件约定

- 一个可独立验收的功能或重构一份文件，命名 `<YYYYMMDD>-<主题>.md`。
- 至少包含：背景/问题、目标与非目标、方案权衡、决定、实施 checklist、验收标准、进度与交接信息。
- 状态使用 `待设计 / 已设计 / 实施中 / 待上线 / 已完成 / 已取消`。
- 需求完成后不删除；把最终设计同步到 `design/`、线上行为同步到 `业务/`、完成事实写入 `changelog/`，再把状态改为“已完成”。
- 不在需求文档中记录凭据、内部主机或用户隐私数据。
