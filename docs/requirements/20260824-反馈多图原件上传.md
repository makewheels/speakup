# 反馈多图原件上传

- 状态：待上线
- 关联总清单：[20260824-结果页与反馈体验总清单.md](20260824-结果页与反馈体验总清单.md)

## 问题与目标

纯文字反馈不足以说明布局、播放、录音或移动端交互问题。结果页反馈和 Settings 全局反馈都需要上传多张图片；区别只在结果页反馈自动关联具体 Attempt。图片是用户业务数据，不是代码资产，必须进入私有 OSS，不能进入 Git。

## 方案权衡

- 不做浏览器压缩或服务端转码，保留原始证据和元数据。
- 通过类型签名和数量/大小上限防滥用，而不是降低图片质量。
- 一次 multipart 请求同时保存反馈和图片，避免“文字已保存、图片失败”造成全局反馈重复。
- 数据库只存 key 和元数据，读取时生成短效签名 URL。

## Checklist 与验收

- [x] 统一图片选择器支持多选、本地预览、移除和已上传图片。
- [x] 结果页反馈保存 `practiceId + attemptId`；全局反馈无练习关联。
- [x] 服务端支持最多 9 张、单张最多 30 MB 的 JPG/PNG/WebP/GIF/HEIC/HEIF 原件。
- [x] 拒绝 SVG、伪装类型、空文件、越权反馈和超限请求。
- [x] OSS 路径为 `feedbacks/{userId}/{yyyyMM}/{feedbackId}/images/{imageId}/original.{ext}`。
- [x] 上传失败清理本次已写 OSS 对象，不留下孤儿文件。
- [x] 测试比较输入和上传 bytes 完全一致，验证无压缩/无转码。
- [ ] Settings 与结果页分别完成一次线上多图提交并读回。
